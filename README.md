# 简明技术中文（STC）

**简明技术中文（Simple Technical Chinese, STC）** 是一套面向技术信息的中文写作规范。

STC 的目标不是把专业内容“写浅”，而是在不损失技术准确性的前提下，使技术文本更：

- **准确**：表达与事实、动作和条件一致。
- **简明**：删除不必要的词语和结构。
- **一致**：同一概念使用同一术语。
- **无歧义**：减少省略、模糊指代和不明确的逻辑关系。
- **可执行**：操作说明能够直接转化为明确动作。
- **易处理**：便于翻译、检索、知识库、机器检查和 AI 处理。

## 适用范围

STC 主要面向：

- 产品说明书
- 操作与维修手册
- 工程技术文档
- 软件帮助文档
- 安全说明
- 标准操作程序（SOP）
- 技术培训材料
- 技术知识库
- 面向机器翻译或 AI 处理的中文技术内容

STC 不以文学表达、公文表达或一般新闻写作为主要目标。

## 基本思想

普通中文允许作者为了语感使用省略、同义替换、长修饰语和上下文暗示。技术文本中的这些特征可能增加理解成本或产生歧义。

STC 优先选择：

> 明确的术语 + 明确的动作 + 明确的对象 + 明确的条件 + 明确的结果

例如：

**不推荐**

> 对电压进行测量。

**推荐**

> 测量电压。

第二种写法没有改变技术含义，但动作和对象更直接。

如果原文有歧义或缺失必要信息，STC 不应猜测。应先指出需要确认的内容，再完成改写。

> **简明不能靠猜。**

## 当前状态

**STC 1.0 Draft 0.4.3**

Draft 0.4 补齐软件与运行环境中的技术中文规则：

- 句长与信息密度
- 问句与回答
- 时间、日期与时区
- 软件界面文本
- 错误消息
- 文件路径、URL 与资源标识
- 命令行与代码操作
- 翻译与本地化
- 安全信息与行业规则的关系

0.4.3 延续 self-compliance cleanup：用 STC 自己的规则审查并修正 STC。重点包括不补充源文本没有的技术事实、区分“保真改写”和“歧义诊断”、合并重复规则，以及修复章节编号和格式漂移。STC 仍不使用固定字数作为句长合规标准，而是根据动作数量、逻辑层级、修饰链和独立信息单元判断复杂度。

## 设计原则

STC 会参考受控语言、简明语言和技术写作领域已有经验，但不会机械复制英语规则。中文有自己的主要歧义来源，例如：

- 主语和宾语省略
- “其、该、此、它”等指代
- 多层前置修饰语
- 并列结构作用范围不清
- 条件、例外和结果关系不明确
- 否定范围
- 同义词在同一文档中任意替换
- 模糊程度词和不确定动作

STC 将优先解决这些中文技术写作问题。

## 版本

STC 使用语义化版本思路：

- **Draft 0.x**：规则仍在形成。
- **1.0**：第一版稳定规范。
- 后续小版本可以增加示例、词汇和解释。
- 规则含义发生不兼容变化时提升主版本。
