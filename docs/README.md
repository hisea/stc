# STC 设计说明与路线图

## 当前阶段

当前目标是完成 **STC 1.0 Draft** 的规则框架，而不是过早冻结细节。

## 近期路线图

### Phase 1：建立核心规则

重点解决：

- 术语一致性
- 省略
- 指代
- 长修饰语
- 并列歧义
- 条件和例外
- 操作步骤
- 模糊程度词
- 数字和单位

### Phase 2：建立语料和测试集

收集真实或现实可成立的：

- 不推荐句
- 推荐改写
- 边界案例
- 规则冲突案例

目标是让每条规则都有可讨论、可测试的实例。

### Phase 3：机器可读规则

定义：

- 规则 ID
- 严重级别
- 自动检测能力
- 误报风险
- 建议修复方式

### Phase 4：STC Checker

建立基础 lint 工具，优先检测高确定性问题，例如：

- 高风险模糊词
- 项目术语不一致
- 多个潜在先行词后的代词
- “进行 + 动作名词”结构
- 未定义缩写

## 暂不决定的问题

以下内容在有足够案例前不急于固定：

- 硬性最大句长
- 每句最大字数
- 全面的禁用词表
- 安全提示等级名称
- 正式认证机制
- 最终许可证

STC 应优先形成可解释的规则，而不是为了“像标准”而设置任意数字限制。
