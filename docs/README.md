# STC 设计说明与路线图

## 当前阶段

当前目标是完成 **STC 1.0 Draft** 的规则框架，并从 Draft 0.3 开始把规则逐步整理为可测试、可机器读取的结构。

## 近期路线图

### Phase 1：建立核心规则

重点解决：

- 术语一致性
- 省略
- 指代
- 长修饰语
- 并列歧义
- 条件和例外
- 操作步骤
- 模糊程度词
- 数字和单位

### Phase 1.5：技术表达和文档结构

Draft 0.3 已覆盖：

- 数字和单位
- 中英文混排
- 缩写和简称
- 标点
- 表格
- 图注和视觉标识
- 交叉引用
- 列表结构

原则是不把纯排版偏好误当作技术语言规则。

### Phase 1.8：软件与运行环境

Draft 0.4 已加入：

- 句长与信息密度
- 问句与回答
- 时间、日期和时区
- 软件界面文本
- 错误消息
- 文件路径和 URL
- 命令行
- 翻译与本地化

完成 0.4 后，人工写作规范主体已基本成型。Draft 0.4.2 进行 self-compliance cleanup：用 STC 自身规则清理示例、章节和内部一致性。下一阶段应减少继续横向加规则，开始定义机器可读规则、严重级别和测试语料。

### Phase 2：建立语料和测试集

收集真实或现实可成立的：

- 不推荐句
- 推荐改写
- 边界案例
- 规则冲突案例

目标是让每条规则都有可讨论、可测试的实例。

### Phase 3：机器可读规则

定义：

- 规则 ID
- 严重级别
- 自动检测能力
- 误报风险
- 建议修复方式

### Phase 4：STC Checker

建立基础 lint 工具，优先检测高确定性问题，例如：

- 高风险模糊词
- 项目术语不一致
- 多个潜在先行词后的代词
- “进行 + 动作名词”结构
- 未定义缩写

## 暂不决定的问题

以下内容在有足够案例前不急于固定：

- 硬性最大句长
- 每句最大字数
- 全面的禁用词表
- 安全提示等级名称
- 正式认证机制
- 最终许可证

STC 应优先形成可解释的规则，而不是为了“像标准”而设置任意数字限制。
